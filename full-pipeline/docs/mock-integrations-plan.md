# Обязательные mock-интеграции

Пользователь утвердил локальные работающие mock-провайдеры вместо платежных систем, карт и любых сторонних данных. Бизнес-сценарий сохраняется; демонстрационные данные и отсутствие реальных операций обозначаются явно. Большая архитектура v2 не меняется.

Выбор реализации: доверенный провайдер внутри существующего .NET backend, вызываемый предметными обработчиками через DI. Отдельный mock-контейнер добавил бы сетевые контракты и запуск еще одного сервиса; одних указаний модели недостаточно. Контракты операций и fixture-ответы входят в AppSpec и фиксируются до генерации исходников. Реальные API/ключи не нужны. Идемпотентные вызовы и результаты сохраняются в отдельной таблице PostgreSQL. Карта отображает локальные GeoJSON/демонстрационные маршруты, без тайлов внешнего сервиса.

- [x] Контракт externalIntegrations: тип, назначение, ссылки на требования, операции с типизированными входами, примером запроса и непустым fixture-ответом; режим только mock.
- [x] Доверенный .NET сервис: валидация, success/declined/unavailable, сохраняемые квитанции, конфликты при повторном requestId с другими данными. Без HTTP к внешним системам.
- [x] Renderer: регистрация DI/маршрутов, manifest/docs/OpenAPI, видимая пометка демо, сеть backend/db без внешнего маршрута. Никаких реальных платежей или сторонних ключей.
- [x] Генерация/исправления: обязательное использование провайдера предметными endpoints, meaningful HTTP assertions с integrationIds, запрет внешних URL/HTTP-клиентов в модельных исходниках.
- [x] Доверенная HTTP-приемка интеграций до предметной приемки и после перезапуска; неизменяемые проверки и manifest входят в frozen hash. Статические проверки исходников/сети до выпуска.
- [x] Python-компиляция и применение worker без прерывания активных запусков. Тесты и новые генерации не запускать согласно указанию пользователя; результаты явно не считать проверенными end-to-end.

## Применение и свидетельства

Worker пересобран и запущен. Python compileall завершился успешно; доверенный C# backend прошел Docker build target build / dotnet publish без запуска приложения. После таймаута автоматического согласования доступа компиляция повторена один раз и завершилась успешно. Первая сборка worker остановилась на сетевом timeout Docker Hub; повторная сборка и применение завершились успешно.

Независимый ревьюер прочитал код без запуска тестов и не обнаружил блокирующих проблем. Замечания об уровне детализации счетчиков, границах идемпотентности и роли driver встроенной парковки отражены в docs/mock-integrations.md. В ответ на сообщение пользователя об admin для публичного приложения worker теперь привязывает роль предметной приемки к роли UI, не изменяя ожидания бизнес-результатов; замены аудируются.

Флажки означают внесенную реализацию. Тесты, новая генерация Qwen и полный цикл этой версии не выполнялись по указанию пользователя. Существующие сгенерированные проекты и их исторические статусы не изменены.

Ограничение: локальные fixture-ответы моделируют согласованный контракт, а не поведение всего внешнего сервиса. Проверки покрытия и обращения к провайдеру не являются формальным доказательством выполнения любого естественно-языкового ТЗ. Runtime-изоляция не распространяется на загрузку образов и зависимостей при сборке или на сам Qwen пайплайна.
