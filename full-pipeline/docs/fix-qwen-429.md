# Qwen HTTP 429: ожидание вместо немедленной остановки

Запуски пользователя `360e5653-143d-4ed3-943a-5c6b447aa304` и `557e900b-28d0-4671-8f11-7d6a47b3328a` заблокированы после HTTP 429. Раньше ModelClient прекращал работу после первого такого ответа. Код 429 сообщает об ограничении обращений; по нему одному нельзя отличить занятость общей очереди от исчерпанной квоты. Изменение исходников приложения не снимает этот лимит.

## Изменение worker

Для HTTP 429 выполняется до четырех дополнительных последовательных запросов (всего до пяти) с тем же заданием, моделью и параметрами. При отсутствии Retry-After паузы растут: 10/20/40/60 секунд плюс случайная добавка до 2 секунд. При наличии Retry-After учитывается число секунд или HTTP-дата; ранее указанного сервером срока повтор не отправляется. Если срок не укладывается в оставшееся окно ожидания, запуск блокируется вместо раннего запроса.

Окно ожидания повторов по умолчанию 180 секунд от первого запроса. Начинать новый HTTP-повтор за пределами окна запрещено. Уже отправленная генерация имеет отдельный LLM_TIMEOUT и может завершиться позже этого окна. Количество повторов и окно настраиваются в .env через LLM_429_MAX_RETRIES (0–8, по умолчанию 4) и LLM_429_WAIT_SECONDS (0–600, по умолчанию 180), передаются worker в Compose.

В журнале и текущей стадии показаны занятость, время ожидания и номер следующего HTTP-запроса. Номер попытки стадии и бюджет исправлений исходников от этих повторов не увеличиваются. Heartbeat продолжает работать в другом потоке; потеря lease отменяет ожидание, без нового запроса. При постоянном 429 запуск завершается blocked, исходники не переписываются из-за ограничения сервиса.

401/403, сетевые ошибки и timeout автоматически не повторяются. Запрос после timeout мог остаться работающим на сервере: повтор способен создать лишнюю генерацию и нагрузку, поэтому эту ситуацию нельзя приравнивать к явному отказу 429.

## Метрики и отчеты

Счетчик modelCalls отражает реальные попытки HTTP, retries — реальные повторные HTTP-запросы; ожидание само по себе вызовом не считается. Отдельный reports/qwen-call-NN.json содержит номера, HTTP-коды, длительности, назначенные паузы и usage по ответам без секретов и тел ошибок. Если хотя бы отклоненный ответ не сообщил usage, суммарные токены отмечаются неизвестными; известный usage успешного ответа остается в отчете отдельной попытки. Нулевое потребление для отклоненного запроса не выдумывается.

Индикатор QWEN_API по-прежнему проверяет каталог /models. Доступность каталога не означает, что chat/completions примет запрос: 429 генерации виден в журнале запуска.

## Применение и ограничения

Новые проверки для восстановления, лимита, Retry-After и отмены добавлены, но не запускались по указанию пользователя. Выполнена компиляция Python; реальный запрос генерации для проверки не создавался. Завершенные blocked-запуски не изменяются. Новая логика используется при следующем запуске обновленного worker. Длительный лимит или исчерпанную квоту следует решать на стороне выданного сервиса; автоматические повторы не гарантируют его доступности.
