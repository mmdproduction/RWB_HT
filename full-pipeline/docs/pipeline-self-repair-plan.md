# Исправление самостоятельной работы пайплайна

Запрос: исправить сам пайплайн, а не вручную подготовленное приложение. Существующий worker/API/стек сохраняются; большой проект архитектуры v2 остается отдельно приостановленным.

По реальному журналу ошибка frontend израсходовала общий бюджет исправлений, затем unhealthy backend исправлялся без исходного исключения и новая правка испортила компилировавшийся C# код. Исправления должны стать локальными, проверяемыми и обратимыми внутри worker.

- [x] Раздельный бюджет двух исправлений на стадию build/test, согласованный с публичными attempt1..3.
- [x] Определять область ошибки (frontend/backend/инфраструктура), передавать профильный контекст и реальные runtime logs.
- [x] Сохранять исходники перед правкой; отклонять изменения вне области ошибки. Каждую кандидатную правку компилировать автоматически; при неуспехе восстанавливать исходники, сохраняя кандидата и диагностику для следующей попытки.
- [x] Повторять запуск, HTTP-приемку и сохранность после каждого принятого исправления; не изменять приемочные сценарии.
- [x] Привязать build/test результаты к hash исходников и неизменяемым проверкам; исключить выпуск кода, не прошедшего проверки.
- [x] Не тратить модельные исправления на сетевые/инфраструктурные сбои. Сохранять результаты транзакций исправления и редактировать секреты из диагностик.
- [x] Собрать/применить worker. Ранее запрещенные пользователем дополнительные тесты и новые генерации не запускать без нового указания; явно отделять внесенные изменения от подтвержденного автономного прогона.

## Состояние применения

Worker пересобран и запущен. Python-модули worker/shared прошли компиляцию; выполнено чтение изменений независимым ревьюером без запуска кода. Дополнительные тесты, новая генерация Qwen и полный автоматический прогон не выполнялись по указанию пользователя. Флажки выше отмечают внесенную реализацию, а не доказательство прохождения полного цикла.

При следующем запуске доказательства будут записаны в `reports/frozen-acceptance.json`, `reports/repair-transactions/` и `reports/pipeline-evidence.json`. Hash исходников охватывает backend/frontend/db; это не контроль всех конфигураций проекта и не доказательство полного соответствия произвольному бизнес-ТЗ. Ранее вручную исправленное приложение не считается результатом нового автономного прогона.
