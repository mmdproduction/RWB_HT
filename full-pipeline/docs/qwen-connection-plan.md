# Отслеживание QWEN_API

Добавить в панель отдельный индикатор подключения с автоматическим обновлением, временем последней проверки, задержкой и короткой историей смены статуса. Проверяется GET /models и точный ID модели, без chat/completions и расходования токенов генерации. Это доступность API каталога моделей, а не гарантия успешного выполнения будущей генерации.

Решение: probe в worker (host network), передача результата через защищенный внутренний endpoint API; frontend читает только обезличенный статус. API находится в другой Docker-сети и не может проверять localhost SSH-туннеля от имени worker. Отдельный внешний монитор/автоматизация не нужны.

- [x] Probe с ограниченным timeout и различением сети, авторизации, лимита, протокола и отсутствия модели; никакие тела ошибок, API-ключи или адреса с секретами не публикуются.
- [x] Cache API: серверное время получения, 45-секундная свежесть, последний успешный отчет, до 20 переходов в памяти процесса. После перезапуска состояние неизвестно до первого отчета.
- [x] Фоновый monitor worker каждые 15 секунд, независимо от активного задания; внутренний endpoint защищен WORKER_KEY.
- [x] Самостоятельный компонент Angular: опрос API каждые 5 секунд, ручное обновление, состояние checking/error/stale, доступная индикация и история. Сбой связи панели с API не выдается за сбой самого Qwen.
- [x] Компиляция Python/Angular, применение API/frontend/worker без прерывания активного запуска. Новые генерации и тестовые suites не запускать по указанию пользователя. Само наблюдение Qwen — явно запрошенная функция.

## Применение

Python compileall и Angular production build завершились успешно. Независимое чтение не выявило существенных дефектов. API/frontend/worker пересобраны и запущены при отсутствии активных заданий; API прошел штатный healthcheck Docker. Через публичный endpoint панели прочитан первый реальный отчет worker: unreachable, модель qwen3.8-27b, HTTP-код отсутствует, generationVerified=false. Это свидетельство работающей доставки статуса и отсутствия соединения на момент проверки, а не установленная причина недоступности.

Новые генерации Qwen, тестовые suites и браузерная QA не выполнялись. Добавленные тесты не запускались. История хранится в памяти, вычисленный stale не добавляется отдельным событием. Документация: docs/qwen-connection.md.
