# Сходство приложений и соответствие стеку презентации

Проверено приложение `f897c74e-5dce-4f25-8a8d-c11b6ff32459` и сравнены общие файлы с предыдущим успешным `1682e13f-9a50-4b04-a6c8-0942d202930a`. Основание требований — присланный слайд «Технологический стек» и подтвержденное разрешение использовать PWA вместо Kotlin. Анализ не меняет исходники и архитектуру пайплайна.

## Почему результат похож

Renderer (`templates/project.py:72`) копирует один каталог assets целиком. В нем заранее написаны общий AppComponent, стили, формы общих сущностей, интерфейс парковки и Parking.cs. Модель может менять только backend/Generated/*.cs и frontend/src/app/generated/*.{ts,html,css}; worker/tools.py запрещает изменять главную оболочку, зависимости и остальные исходники.

Для capability parking AppComponent автоматически выбирает готовую страницу parking (`templates/assets/frontend/src/app/app.ts:43`). Поэтому первым пользователь видит один и тот же заранее подготовленный экран. Сгенерированный GeneratedPanel находится на другой вкладке «Приложение». У последнего проекта он представляет собой форму проверки зоны по координатам.

Побайтовое сравнение двух успешных проектов подтвердило одинаковые frontend/src/app/app.ts, frontend/src/styles.css и backend/Parking.cs. app.html отличается после добавления общего предупреждения о mock-интеграциях, но сохраняет готовый парковочный экран. Это архитектурная причина сходства; повышение temperature само по себе ее не устранит.

Фактически текущая модель создает расширения готового приложения, тогда как значительная часть интерфейса и бизнес-логики парковки уже задана. Фиксированный Angular/.NET-стек не требует одинаковой композиции экранов, сценариев и стилей.

Модель не может заменять Angular/.NET/PostgreSQL через обычный patch: зависимости и инфраструктура находятся вне разрешенной области. Это техническое ограничение, а не только текст промпта. Однако версия PostGIS задается установкой пакета без точного pin, образы .NET закреплены по основной ветке 10.0, а не digest. Слайд не требует точного patch этих компонентов. Совпадение Debian-пакета PostgreSQL подтверждено именно для проверенного контейнера; отдельного валидатора полного набора требований слайда сейчас нет.

Сам пайплайн использует Python/FastAPI. Серверная бизнес-логика созданного приложения использует C#/ASP.NET Core; Python присутствует как вспомогательные скрипты приемки. Эти два стека нельзя смешивать при оценке результата.

## Вывод и направление исправления

Основной стек созданного приложения соблюден, но заявлять полное соответствие всему слайду нельзя: Kafka отсутствует, фактического CI-прогона на GitLab 19.4.2 нет. Задача проверки строгого стека должна включать обязательный manifest и блокировку отсутствующих обязательных компонентов; наличие шаблона само по себе не покрывает весь перечень.

Для устранения сходства необходимо сохранить техническую основу, версии и ограничения безопасности, а предметные экраны, навигацию и бизнес-обработчики формировать под требования. Готовый Parking.cs и парковочный экран не должны автоматически становиться основной реализацией каждой задачи с упоминанием парковки. Это направление изменения границ генерации; в рамках текущего анализа оно не реализовывалось.

Проведены только чтение исходников/lock-файлов/отчетов, сравнение файлов и чтение версий уже работающих контейнеров. Новые тесты, сборки, генерации и изменения приложения не запускались.
