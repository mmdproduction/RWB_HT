# Backend unhealthy и неудачное автоисправление

Кейс: `6dc67713-7c97-44f8-b639-49519113ebfd`.

По сохраненным артефактам и присланному журналу:

1. Angular ссылался на отсутствующий trackById. Первая попытка добавила метод, следующая сборка frontend завершилась успешно.
2. GeneratedExtensions объявлял GET handler с параметром Db db, а доверенный Program.cs не регистрировал Db в IServiceCollection. ASP.NET не мог определить его как сервис и мог трактовать как тело GET-запроса, что нарушает привязку endpoint при запуске.
3. Старый исполнитель передавал модели только unhealthy, без исключения процесса. Последняя попытка внесла в ранее компилировавшийся backend JsonNode.ValueKind и неоднозначный JsonValue.Create(null), после чего сборка упала. Исходный runtime stacktrace старый исполнитель не сохранил; конкретная строка startup exception не восстановлена.

Локальные изменения действующего пайплайна:

- Шаблон регистрирует Db и NpgsqlDataSource до Build().
- При ошибке запуска сохраняются backend/db logs и состояние контейнеров до исправления и очистки. Они передаются модели вместе с read-only Program.cs, schema.sql и контрактом Db.
- В генерацию/исправление добавлены точные ограничения JsonNode API, сохранения работающего кода и запрет маскировать исключения БД успешным пустым ответом.
- Отдельная исправленная копия текущего проекта подготовлена в repaired-projects/parking-6dc67713; старые артефакты не перезаписывались.

Архитектура v2 остается черновиком и не внедрена. Дополнительные тесты, запуск исправленной копии и новые генерации не выполнялись.

Обновление после пользовательского «продолжай»: исправленная копия собрана и запущена без новой генерации, Compose up --build --wait вернул0; все три сервиса healthy. Адрес http://127.0.0.1:32782. Тестовые сценарии/браузерная приемка не запускались. Первоначальный стек ошибки старого контейнера по-прежнему недоступен; фактический успешный старт исправленной копии зафиксирован отдельно.
