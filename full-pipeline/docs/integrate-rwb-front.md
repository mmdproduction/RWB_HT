# Интеграция фронтенда RWB_HT с AI-пайплайном

Источник оформления: https://github.com/mmdproduction/RWB_HT/tree/front

Зафиксированная версия: `0142d5b666b8476d08dec29f2fea86e73f80e96f`.

## Решение

Обновление оформления с сохранением функций исходной панели описано в [unified-console-style.md](unified-console-style.md). Компоненты проводника и Qwen теперь используют общую тему, а страницы запуска — общие вкладки и шапку.

Использовать страницы и оформление ветки front в существующем сервисе frontend. Заменить браузерную симуляцию настоящим HTTP-клиентом существующего API. Backend, worker, БД, механизм генерации и фиксированный стек генерируемых приложений сохраняются.

Альтернатива — отдельный второй frontend — потребовала бы поддержки двух сборок и двух интерфейсов. Перенос только стилей не сохранил бы страницы и навигацию сокомандника. Выбран перенос страниц с адаптацией их логики.

## Обязательное поведение

- Создание запуска отправляет полный текст требований до 100 000 символов в POST /api/runs.
- История, стадии, статусы, метрики, сообщения и ссылки поступают с сервера. Неизвестный запуск показывает ошибку, а не вымышленный успех.
- Журнал читается с курсором; запросы не перекрываются, останавливаются при уходе со страницы и после получения итогового состояния.
- Страница результата доступна и при сбое: показывает реальный статус, исходники, отчёты, бизнес-задачу и скачивание ZIP.
- Компоненты просмотра файлов и мониторинга Qwen сохраняются.
- Старые ссылки /?run=UUID перенаправляются на страницу этого запуска.
- Маршруты /new, /status/:runId, /result/:runId открываются напрямую через Nginx.
- Angular и Material панели остаются на 20.1.6. Стек создаваемых приложений не меняется.

## Запуск и обновление

Из корня full-pipeline при уже работающих API/worker/БД:

```bash
docker compose up -d --no-deps --build frontend
```

Панель: http://127.0.0.1:8090/new. Существующие ссылки `/?run=UUID` открывают страницу состояния соответствующего запуска. Прямая ссылка результата: `/result/UUID`.

На VM следует переносить полный актуальный full-pipeline и разворачивать его отдельно от прототипа в /home/team19/backend; инструкция — [deploy-vm.md](deploy-vm.md). Порты прототипа 8000/4022 не используются этой панелью: её Nginx направляет /api/ в контейнер API нашего Compose. После копирования новых файлов в уже установленный ~/rwb-pipeline достаточно команды выше, при необходимости с sudo.

Если API нашего пайплайна на VM ещё не установлен, один этот frontend с прототипом main.py работать не будет: различаются формат запуска, состояния, журнал и файловый API. Нужна установка всего Compose по deploy-vm.md.

Inter загружается браузером с Google Fonts, как в исходном оформлении команды; при его недоступности используется системный шрифт. Общая шапка и вкладки не зависят от иконочного шрифта. Сборка не загружает шрифты.

## Ручная приёмка пользователем

Дополнительные проверки агентом не запускаются. Для самостоятельной проверки: открыть историю существующих запусков, успешный результат с файлами и ZIP, ошибочный запуск с сообщением, неизвестный UUID и старую ссылку `/?run=UUID`. Новый запуск отправляет реальную задачу Qwen.

## Результат реализации (31.10.2026)

- Перенесены три страницы и оформление из указанной версии ветки front.
- RunsService использует существующие API /api/runs, /logs и /download; статус успеха не вычисляется из таймера или процента прогресса.
- История обновляется каждые 5 секунд, активный запуск — каждые 3 секунды. Запросы страницы состояния не перекрываются; журнал читается после состояния запуска, чтобы не потерять последние сообщения. Журнальные страницы дочитываются до пустой страницы, включая итоговый запуск.
- При ошибке остаются видны реальные данные и сообщение; неизвестный запуск не подменяется фиктивным результатом.
- Сохранены RunFilesComponent и QwenStatusComponent. Прежний файл src/app.ts оставлен как совместимый экспорт нового корневого компонента.
- Сборка docker compose build frontend завершилась успешно. Angular: 20.1.6, Router: 20.1.6, Material: 20.1.6; исходный lockfile команды с плавающими версиями не используется.
- Обновлён только локальный контейнер frontend; контейнер запущен, порт 127.0.0.1:8090.
- Тесты, браузерная приёмка и генерация Qwen не запускались. VM и удалённый репозиторий не изменялись.

Отдельное чтение кода выявило и привело к исправлению гонки завершающих логов и конфликта стилей баннера ошибочного результата. Старые ссылки обрабатываются функцией перенаправления корневого маршрута. Поведенческие проверки этих изменений не запускались по просьбе пользователя; выполнена повторная сборка.
