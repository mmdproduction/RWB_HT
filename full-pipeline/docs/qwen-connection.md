# QWEN_API — подключение и мониторинг

В верхней части панели отображается отдельный блок QWEN_API: состояние, точная модель, задержка HTTP-ответа, время последнего отчета и последнего успешного ответа. Можно вручную обновить данные и раскрыть историю переходов. Worker проверяет соединение каждые 15 секунд; панель получает сохраненный статус каждые 5 секунд, в том числе когда нет активных запусков.

## Что проверяется

GET `<LLM_BASE_URL>/models` из сети worker, с серверным LLM_API_KEY и поиском точного LLM_MODEL. Worker имеет доступ к тому же SSH-туннелю, через который идет генерация. Контейнер API не пытается проверить собственный localhost вместо localhost worker.

Статусы различают отсутствие настроек, недоступность сети, timeout, отказ доступа (401/403), ограничение запросов (429), ошибку сервера, неверный endpoint/ответ и отсутствие модели. Зеленый статус означает, что API каталога отвечает и модель найдена. Он не доказывает возможность выполнить следующий chat/completions: очередь генерации, другой контроль авторизации или нехватка ресурсов могут проявиться только в настоящем запросе. Монитор не вызывает генерацию и не расходует ее токены.

## Передача и свежесть

Worker отправляет результат в POST `/internal/services/qwen` с X-Worker-Key. Публичный GET `/api/qwen/status` возвращает только фиксированное сообщение состояния, модель, HTTP-код, задержку и временные метки. Ни API-ключ, ни Base URL, ни тело ошибок стороннего API не передаются браузеру. Доступ к внутреннему endpoint без ключа запрещен. Ручное «Обновить» перечитывает последний отчет; новый сетевой probe выполняется по расписанию worker.

Если в течение 45 секунд нет нового отчета, зеленый статус заменяется на «Нет свежих данных». Потеря связи панели с ее API отображается как неизвестное состояние Qwen, а не как доказанная недоступность Qwen. Смена состояния хранится в памяти API: до 20 переходов, после перезапуска история начинается заново. Пропажа worker дает текущее состояние stale, но отдельным событием истории не записывается.

Мониторинг не меняет стадии, метрики токенов и результаты запусков. Существующие генерации не переписываются. Загрузка интерфейса и запись отчетов не создают новых задач.

## Проверка изменения

Python и Angular скомпилированы; выполнено независимое чтение изменений без блокирующих замечаний. Регрессионные тесты добавлены, но не запускались согласно указанию пользователя. Новые генерации и chat/completions для проверки не выполнялись. После применения worker запускает сам запрошенный мониторинг.
