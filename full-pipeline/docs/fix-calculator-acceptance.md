# POST без тела в сценарии калькулятора

Запуск: `7cf5a8a8-2e31-483c-9de5-334ee4c1b10d`.

По сохраненным исходникам и логам: оба шага POST `/api/generated/calculator/validate` в `domain-acceptance.json` не содержат `body`. C#-обработчик принимает обязательный JsonElement и ожидает operandA/operandB/operation. Поэтому ASP.NET возвращает400 с пустым телом до входа в обработчик. `contains` описывает ожидаемый ответ и не является телом запроса. Исправление только backend не может восстановить отсутствующие входные данные сценария.

Корректные входы для зафиксированных ожиданий:

```json
[
  {"method":"POST","path":"/api/generated/calculator/validate","body":{"operandA":2,"operandB":3,"operation":"add"},"status":200,"contains":{"valid":true,"result":5}},
  {"method":"POST","path":"/api/generated/calculator/validate","body":{"operandA":5,"operandB":0,"operation":"div"},"status":200,"contains":{"valid":false,"error":"Ошибка: деление на ноль"}}
]
```

Изменения пайплайна:

- POST/PUT без явного JSON body отклоняются на стадии генерации, до сборки.
- Некорректный пакет генерации возвращается Qwen с конкретной ошибкой; максимум три попытки генерации. Лимит исправлений исходников остается прежним — два.
- Промпт явно различает request body и response contains и показывает примеры входов.
- Автоисправление получает неизменяемые HTTP-сценарии, а диагностика содержит номер шага, method/path, request body, ожидаемый и фактический ответ.
- Добавлены указания по уже встречавшимся ошибкам C#: System.Text.Json не implicit using; JsonNode нельзя объединять через ?? с anonymous type.

Старый завершенный запуск и его артефакты не переписаны. После обновления worker создайте новый запуск с теми же требованиями. Дополнительные тесты/генерация исполнителем не запускались по указанию пользователя; результат повторного запуска предстоит проверить пользователю.
