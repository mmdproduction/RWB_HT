# Исправление покрытия integrationIds

Пользовательский запуск `5cdc319a-475f-4f69-9685-b2000bbb907f` остановился на проверке успешных сценариев для `maps-spb`. В AppSpec этот mock-провайдер карт связан с REQ-001 и REQ-005, операция get_zones получает lat/lng и возвращает локальную GeoJSON FeatureCollection.

## Обнаруженные проблемы

Общий пример JSON-ответа генератору не содержал integrationIds, хотя отдельное правило и валидатор требовали его. При повторе модель получала краткую ошибку без полного предыдущего предложения. Отклоненные ответы генерации не сохранялись: из этого старого запуска нельзя точно восстановить, какие сценарии и связи вернула модель. Утверждать конкретное содержимое отсутствующего ответа нельзя.

## Изменение

- Worker добавляет связи integrationIds по пересечению уже объявленных requirementIds сценария и провайдера. Это индекс трассировки, а не свидетельство выполнения. Тела запросов, статусы и contains не меняются; чужие/неизвестные ID не исправляются молча. Привязки записываются в acceptance-integration-audit.json с executionVerified=false.
- Отсутствующий успешный сценарий с содержательным contains по-прежнему блокирует генерацию. 204 без проверки бизнес-результата покрытием интеграции не считается. Отказные сценарии также обязательны.
- Проверка реальных успешных И отказных вызовов каждого провайдера бизнес-обработчиками сохранена. Контрактные прямые вызовы и одни метки integrationIds ее не заменяют.
- Генератор заранее получает отдельную матрицу покрытия с точными ID провайдеров, requirementIds, операциями и примерами входов. Пример JSON исправлен. При повторе передаются предыдущие исходники/сценарии и явные требования к исправлению.
- Все ответы сохраняются в generation-attempt-N.json, ошибки — в generation-validation-N.json. Непринятый исходный патч откатывается, включая новые файлы, чтобы следующая попытка начиналась с чистого состояния.

Python скомпилирован. Регрессионные проверки добавлены, но не запускались согласно указанию пользователя. Новая генерация и полный цикл этой версии не выполнялись. Исторический неудачный запуск не переписывается; изменение применяется для новых запусков worker.
